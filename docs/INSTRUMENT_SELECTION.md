# 音源選定とライブラリ索引

## 責務

呼び出し元AIは、利用可能なプラグインと内部ライブラリを先に調べ、曲調・役割・奏法に適する候補を試聴して選ぶ。選定理由、実際の保存状態、評価根拠を残す。MCP server instructionsとルートAGENTS.mdにこの手順を明記した。

AIDAWは登録パスの検出、パッチ索引、検索、保存プリセットと試奏音声の関連付けを提供する。音色評価は既存の呼び出し元による音声確認を使用する。

## APIと保存形式

- `content_discover_roots`: macOSのNI ContentDir/ContentPathとWindowsのNIレジストリ、既知のユーザー保存先を検出。ライセンスキーは収集しない。
- `content_register_root`: その他のライブラリを明示登録。原本を移動・編集しない。
- `content_index`: NKI/NKM/NKSN/NKSF/NKSFX、Battery NBKT、MASSIVE NMSV、Reaktor ENS/RKPLR等を件数・時間上限付きで索引化。シンボリックリンク・Samplesディレクトリは追わない。中断・読めない場所を報告し、不完全スキャンで既存索引を消さない。
- `content_search`: ライブラリ名、ファイル名、相対パス、ホスト系列で検索。ページングと利用候補プラグインを返す。
- `kontakt_preset_import`: Windows版Kontakt 8 VST3 8.13.0へNKI/NKSNを読み込み、発音、状態保存、別インスタンスへの復元後発音を検証して再利用可能なpreset IDを返す。通常はprobe_pitch=60。音域が限定された音源では演奏可能なMIDIノートを指定する。
- `content_bind_preset`: 呼び出し元が特定したパッチと、正確な保存プリセット由来の試奏記録を関連付ける。音声ハッシュを検証。ファイルの音色との同一性を自動証明したとは扱わない。

索引は `PluginLibrary.aidaw/state/content-catalog.json`、処理記録は同プロジェクトの `jobs/<id>/`。スキーマ1。ローカルパスはマシン固有であり、別環境では再検出・再索引する。作品の持ち運びには既存の収集済みアセットとフリーズ音声を使う。

## 標準音源への代用防止

新規プロジェクトは `instrument_policy=plugin_first` が既定。builtin/Apple DLS/QuickTime等の追加・音源交換を拒否する。明示的に基本音源を使う用途だけ作成時に `allow_basic` を指定する。通常のcatalog_searchは基本音源を除外し、`include_basic=true` でのみ含める。既存作品のインポート・再生と、既存トラックの音量などの編集は維持する。この設定はセキュリティ境界ではなく制作規約であり、音質の自動保証ではない。

## 対応範囲

索引はファイル名・登録情報の根拠であり、NKSの音色タグの完全解析、コンテナ内部スナップショット列挙、全ディスク検索ではない。Windows版Kontakt 8 VST3 8.13.0のNKI/NKSNは対応済みだが、別OS・別版へ推測適用しない。発見した全音源がそのまま演奏可能という意味ではなく、対応済みインポーターの実ロードと発音検証、または確認されたプラグイン保存状態を使う。プラグイン未導入、認証、サンプル不足もロード時に別途確認する。

Windowsの登録検出とKontaktインポートを実装済み。Kontaktインポート時だけプラグイン画面を一時表示してOSのファイルドロップを行い、直後に閉じる。音色の音楽的評価まで自動で済んだとは扱わない。

標準セットアップには **AIDAW GM（FluidR3）・EQ・Limiter・Reverb** が含まれます。手持ち音源がない環境での制作、またはユーザーが標準音源を希望する場合、AIDAW GMは `plugin_first` のまま明示的に選択できます。先に利用可能な音源・内部ライブラリを比較する方針と、指定された音源のロード失敗を黙って代用しない規約は維持します。詳細: [標準音源・エフェクト](STARTER_PACK.md)。
